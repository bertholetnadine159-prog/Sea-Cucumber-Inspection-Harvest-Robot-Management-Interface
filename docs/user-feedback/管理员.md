# 管理员反馈：海参捕捞机器人 SeaUI（账号与设备管理员）

- 画像：系统管理员，管账号（建号/停用/改密/审计）和设备（RDK 地址/链路诊断），最在乎"权限拦不拦得住、审计记不记全、动线快不快"。
- 实测方式：真实执行。在 backend/ 目录用独立实例 `ROV_BACKEND_MODE=sim ROV_WS_PORT=18713 ROV_API_PORT=15013 ROV_DB_PATH=data/uf_admin.sqlite3 python app.py` 后台启动，`curl http://127.0.0.1:15013/api/health` 返回 `{"ok": true, "backend_mode": "sim", ...}` 就绪；REST（urllib，Python 计时）+ WS（`ws://127.0.0.1:18713`，`{"type":"auth","action":"login","token":...}`，websockets 16.0）走完整管理动线；界面逐行走查 `rov_flutter/lib/features/**`（admin_panel_desktop / settings_desktop / login_screen / app_header / app.dart / rov_backend_service / user_session）。
- 说明：本机未拉起 Flutter 桌面壳（未跑 `flutter run`），界面体验基于逐行代码走查 + 真实后端协议响应。

## 总体评分：3.5 / 5

后端权限与审计是我用过的最让人安心的一档：operator 六种危险命令全部被硬拦、每次被拦都有名有姓进审计、未鉴权连接一个字节流都不推。但管理动线的界面缺口很大：我在界面上**造不出 operator 角色**、用户只能增/删不能改角色/停用/重置密码、退出登录不吊销服务端会话、命令被拒界面毫无提示。权限"拦得住"靠后端，界面还欠火候。

---

## 满意（带证据）

1. **危险命令角色拦截真实可靠，这是本次最核心的安心点**。REST 侧：operator token `POST /api/command {"command":"arm"}` → `403 {"ok":false,"error":"forbidden"}`（24.9ms）；WS 侧：operator 连接发 `arm` → `{"type":"ack","command":"arm","success":false,"message":"forbidden"}`（5.6ms）。六种危险命令逐一实测全拦：`arm/disarm/esc_calibrate/correct_param/init_escs/motor_diagnostic` 全部 `forbidden`（5.6–11.9ms）；同 token 发 `emergency_stop`、`lightOn` 放行（`success:true`）——**急停对任何角色永远畅通**，安全优先级设计正确（backend/app.py:74-82 危险命令白名单、app.py:528-533 / 831-834 双通道同规则）。
2. **超管侧同命令全通**：admin WS 发 `arm/disarm/motor_diagnostic/emergency_stop` 全部 `success:true`（5.4–9.9ms，sim 模式）。权限矩阵不是"一刀切"，是精确到角色的。
3. **审计日志完整到让我放心**：`GET /api/logs` 里 operator 六次被拦命令全部落库 `ok=0` 且带用户名（`02:49:56 user=op_wang cmd=arm ok=0`）；连我故意不带 token 的裸命令也记为 `user=anonymous ok=0`（02:41:09 / 02:49:24 / 02:49:19 三批）。事后追责有据可查（app.py:519-524 匿名落库、app.py:529 / 832 被拦落库）。
4. **鉴权闸门是真的**：两条连接各监听 2 秒做泄漏检查，auth 前收到消息数为 **0**；auth 后首帧 0.0s、3 秒窗口 42 帧（14/s，sim 上限）+ status 1/s + sensors。hello 30.1ms、auth 6.7ms。未登录一个字节都拿不到（app.py:354-356、446-447）。
5. **管理面板全部真数据，无假 KPI 复活**：`/api/stats` 22.2ms 返回 `users/sessions_active/control_logs_24h/sensor_readings_24h/db_size_mb/uptime_s/backend_mode`，与库内事实一致（建号前 users=1，建号后=2）；界面头部注释明确"删除假 KPI…无真实数据时显示空态/错误态，不回退合成数据"（admin_panel_desktop.dart:1-9），统计卡带 StaleBadge 断链提示（admin_panel_desktop.dart:678-681，65s 阈值）、加载骨架/空态/错误态齐备（admin_panel_desktop.dart:780-793）。
6. **超管初始口令强制改密闭环**：实测初始口令登录返回 `must_change_password:true`；界面在改密成功前不进主界面且弹窗不可点遮罩关闭（login_screen.dart:82-105，`barrierDismissible:false`）。
7. **危险账号操作有兜底**：`DELETE` 超管 → `400 {"error":"super admin cannot be deleted"}`（实测，database.py:233-239 保护）；停用账号登录 → `401`（实测 enabled=false 后 `POST /api/login` 被拒）；改密吊销全部旧会话（database.py:231 `DELETE FROM sessions WHERE user_id = ?`）。删除用户有确认弹窗"此操作不可恢复"（admin_panel_desktop.dart:1105）。
8. **动线快**：登录 106.1ms、`/api/stats` 22.2ms、用户列表 3.3ms、建号 86.1ms、WS ack 全部 ≤14ms。没有任何可感知卡顿。
9. **风格与资源纪律在线**：管理面板/设置页保持 GitHub light（`backgroundLight #F8FAFC` + 白卡 + 1px 描边，app_colors.dart:46，符合 docs/STYLE_SPEC.md §1/§2.1）；30s 统计轮询 Timer 在 dispose 里取消（admin_panel_desktop.dart:83），设置页控制器全部 dispose（settings_desktop.dart:68-73）——没看到会泄漏的计时器。

## 痛点（带证据）

1. **界面上根本造不出 operator 角色——权限体系的第一环在 UI 断了**。添加用户对话框的角色是**手填文本框**（admin_panel_desktop.dart:1024-1031，hint"管理员 / 超级管理员"），提交映射写死 `role.contains('超级') ? 'super_admin' : 'admin'`（admin_panel_desktop.dart:1064）。我填"操作员/operator"也会被建成 admin。结果：我作为管理员只能绕 REST API 手工造出能被 403 拦截的账号（本次实测就是这么干的）。界面承诺的权限体系对纯界面用户形同虚设。
2. **用户管理只有"增/删"，改角色、停用、重置密码全无入口**。用户行上唯一操作是删除按钮（admin_panel_desktop.dart:967-974）。后端明明支持 `PUT /api/users/:id`（role/real_name/enabled，app.py:884-898）和 `PUT /api/users/:id/password`（app.py:868-883），但界面不暴露。员工离职要停用、换岗要改角色、忘密码要重置——三件日常事都只能绕 API 或直接动库。
3. **退出登录不吊销服务端会话**。`UserSession.logout()` 只清本地并 `detachAuth()`（user_session.dart:180-190；rov_backend_service.dart:448-453 仅 `_authToken = null`）；协议里有 `{"type":"auth","action":"logout"}`（app.py:456-464，服务端会删会话行），但客户端全库 grep 无一处发送。叠加 12h 会话 TTL（database.py:26），实测我这个只测了十几分钟、仅 2 个用户的库，`sessions_active` 已经 **9**（`/api/stats` 实测）。令牌一旦被拷走，"退出登录"毫无杀伤力。
4. **命令被拒界面零反馈**。服务层收 ack 只 `debugPrint`（rov_backend_service.dart:960-963 `case 'ack'`），`forbidden/unauthorized` 不会以任何形式浮出给操作员。操作员点了没权限的动作 = 石沉大海。只有管理面板为 set_rdk_config 私搭的 `_UiSocketRequest` 会回读 ack（admin_panel_desktop.dart:1424-1470），其余命令通道全部静默。
5. **重复用户名报数据库原文**。实测重名建号 → `400 {"error":"UNIQUE constraint failed: users.username"}`，ApiClient 原样透传 `data['error']`（api_client.dart:73），管理员在界面上会看到 "UNIQUE constraint failed: users.username" 这种开发人员报错。
6. **无密码策略**。实测 `POST /api/users {"username":"weakpw","password":"1","role":"operator"}` → `200 ok`，且 `password:"1"` 能成功登录（测完已删）。管理员的"初始密码"防线完全靠自觉。
7. **导航无角色过滤**。五个页签写死（app_header.dart:78-99），operator 登录照样能看到"管理员/数据分析"，点进去就是一屏 403 错误态。后端挡得住，界面不预告，每次都是撞墙式发现。
8. **设置页自助改密不验旧密码**。弹窗只填新密码+确认（settings_desktop.dart:197-207），后端仅需 Bearer（app.py:868-883）。工作站忘锁屏时，路过的人 10 秒就能接管账号——对单机海上下文的系统不算致命，但至少该让管理员可关可开。
9. **"活跃会话"统计口径失真**。只按 `expires_at >= now` 计数（database.py:284-286），重复登录不断累积、无人清理，2 用户库显示 9 个"活跃会话"，我无法用它判断有没有异常登录。

---

## 建议（按优先级）

1. 添加用户对话框角色改下拉框（超级管理员/管理员/操作员），映射补全 `operator`；重名时提示"用户名已存在"（后端把 UNIQUE 冲突翻译成人话）。
2. 用户行补"编辑（角色/停用）/重置密码"操作，后端 `PUT /api/users/:id` 与 `/password` 已就绪，纯界面工作量。
3. 登出走 WS `auth/logout` 真正吊销会话；`sessions_active` 按 user 去重，或后端启动时清理过期会话行。
4. 服务层 ack `success=false` 时统一浮出 SnackBar（区分"权限不足/参数错误/后端未连接"），别再让 `forbidden` 进黑洞。
5. 后端加最小密码策略（长度 ≥8），或至少在管理面板建号时给强度提示。
6. operator 角色登录后隐藏/置灰"管理员""数据分析"页签，把后端的 403 变成界面的预告。
