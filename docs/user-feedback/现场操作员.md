# 用户反馈：现场操作员（开船 / 看视频 / 抓海参）

> 实测日期：2026-09-21 · 角色：SeaUI 水下海参捕捞机器人现场操作员
> 实测方式：真实启动独立后端实例 + 真实协议操作（REST/WS），全部计时数据来自本机真实执行；
> 界面部分为代码走查（rov_flutter/lib/features/**），未运行 Flutter 应用，已如实标注。

## 一、实测环境与方法

- 后端独立实例：`cd backend && ROV_BACKEND_MODE=sim ROV_WS_PORT=18711 ROV_API_PORT=15011 ROV_DB_PATH=data/uf_operator.sqlite3 python app.py`
- 就绪确认：`curl http://127.0.0.1:15011/api/health` → `200 {"ok": true, "backend_mode": "sim", ...}`，本机 REST RTT ≈1.6ms
- REST 登录：`curl -X POST /api/login`（zmm）→ `time_total=0.0826s`，返回 `ok=true, role=super_admin, must_change_password=true`（超管初始口令强制改密，契约§4 生效）
- WS：`ws://127.0.0.1:18711`，auth 用 `{"type":"auth","action":"login","token":...}`；测量脚本：Python asyncio + websockets 16.0（`time.perf_counter()` 计时）
- 落库验证：`uf_operator.sqlite3` 中 `control_logs` 全量审计（含我故意发的无 token move，记为 `anonymous, ok=0`）；`sensor_readings` 全部 `source='sim'`（sim 数据不混入真实链路，溯源铁律生效）

## 二、实测数据（响应速度）

| 项目 | 结果 |
| --- | --- |
| WS hello（connect→hello） | 0.0ms（连上即回） |
| WS auth RTT（token 形态） | 6.6ms，`auth_result success=true user=zmm` |
| **首帧（auth→frame）** | **7.2ms**（connect→frame 7.3ms），单帧 25.6KB |
| 帧率（5s 采样） | 13.99 fps（sim 源 15fps，基本满帧）；status 1Hz；sensors 0.4Hz（sim 遥测 2s 一拍） |
| **move ack ×20** | **min 8.2 / p50 9.2 / mean 9.9 / max 19.8 ms**，全部 success |
| **stop ack ×10** | **min 8.0 / p50 9.0 / mean 8.8 / max 9.7 ms** |
| 灯光/吸捕（lightOn/grab/release/lightOff） | 8.6~9.4ms 全 success（ack.command 为翻译名 light_on/suction） |
| **emergencyStop ×3** | **10.0 / 11.8 / 13.1 ms**，ack `command=emergency_stop success=true` |
| 无 token move | 8.1ms 即回 `unauthorized`（拒绝不执行） |
| 未鉴权连接 2s | 收到流式消息数 = 0（推流闸门有效） |
| 坏 token auth | `success=false「会话无效或已过期，请重新登录」` |

**结论：桥接层响应非常跟手。** 首帧 7ms 级、控制 ack 个位数~两位数毫秒、急停 ack ≈10ms，这在现场是"指哪打哪"的手感（真实链路还要叠加网线到 RDK 的网关段时延，但桥接层不是瓶颈）。

## 三、满意（带证据）

1. **鉴权与推流闸门真实有效**：未鉴权连接 2 秒 0 条流式消息；无 token 命令 8.1ms 被拒且落审计（backend/app.py:516-524）；坏 token 回明确中文提示。登录→auth→推流的动线一次走通。
2. **三通道真实数据绑定完整**：`videoFrameNotifier`（rov_backend_service.dart:294, 1022）→ 主控页视频/检测叠加（main_control_desktop.dart:286-288）；`telemetryNotifier`（rov_backend_service.dart:298, 480）→ 右栏状态卡（main_control_desktop.dart:976-1002）；`connectionNotifier` → 标题栏芯片（main_control_desktop.dart:185-206）。无源一律 `--` 不造假：深度卡（main_control_desktop.dart:744-746）、飞控键值行（1145-1158）、水温卡（1212-1216）。
3. **断链提示可信**：StaleBadge 5 秒阈值 + 每秒自查 + 自动消失（stale_badge.dart:39-49, 77-98），报警卡/运行状态/飞控/水温四处都挂了（main_control_desktop.dart:1029, 1055, 1130, 1197）。
4. **急停球设计专业**：按住 500ms 充能防误触、拖动取消充能、充满立即直发免确认（emergency_orb.dart:67, 155-157, 217-226）；未连接时如实报「急停未发出」而不是假成功（emergency_orb.dart:182-189）；触发有全屏红闪 + 重触感确认（174-178）。动画控制器全部 dispose（125-133）。
5. **松手即停的手感**：键盘 WASD 按下推进/松开 stop（main_control_desktop.dart:79-113），方向钮 onTapDown 发送 / onTapUp+onTapCancel 双兜底 stop（847-891, 943-971）；配合后端 100ms 看门狗重发（backend/app.py:574-585），失联自动回中。
6. **空壳没有复活**：主控页明确不还原声呐/激光/自动巡航假开关（main_control_desktop.dart:800-803），视频源只剩真实 RDK 流（1795-1798）；旧版假坐标卡已换成真实 ms5837 深度。

## 四、痛点（带证据）

1. **【重要】命令 ack 在 UI 层被丢弃，"已急停"可能不真实**：Flutter 服务层收到 ack 只 `debugPrint`（rov_backend_service.dart:960-963）。后端在已连接但会话失效时会拒绝命令（我实测：`success=false message=unauthorized`）。此时急停球 `_fireStop` 只要消息写进通道就 `sent=true` → SnackBar 报「已急停」（emergency_orb.dart:182-189），但后端实际没执行。急停是保命功能，"已连接未鉴权"这条失败路径必须闭环。
2. **主控页急停按钮零反馈**：`onPressed: () => _backendService.emergencyStop()` 返回值直接丢弃（main_control_desktop.dart:1325）——断链时按了没有任何提示；operate 页同样命令却会报「急停未发出：后端未连接」（operate_desktop.dart:985-988）。同一动作三个入口两种反馈口径，现场最容易慌。
3. **operate 页急停带确认对话框，应急偏慢**：先弹「确定要执行紧急停止吗？」再发命令（operate_desktop.dart:973-988）。急停球用 500ms 充能替代确认（更快且有防误触），三个入口（急停球直发充能式 / operate 确认对话框 / 主控页直发无反馈）交互不一致，肌肉记忆容易打架。
4. **主控页抓取没有释放**：空格=抓取（main_control_desktop.dart:94-96，底部键帽提示「抓取采集」777 行），但整页 grep 不到任何 `release()` 入口——吸泵会一直转，得切到 operate 页找「释放（吸力 0%）」（operate_desktop.dart:468-473）。抓海参时单屏作业动线断了。
5. **键盘焦点静默丢失**：WASD 靠 `KeyboardListener autofocus`（main_control_desktop.dart:118-121），但拖完「推进器动力」滑块（1374-1389）焦点落在 Slider 上，再按 W 无反应，页面没有重新取焦逻辑。现场表现为"键盘突然失灵"。
6. **帧元数据被桥接层剥掉，UI 的 fps/分辨率/≈链路时延/检测框到不了真实链路**（代码走查推断，sim 下无法复现）：UI 期望 frame 消息带 `width/height/fps/sent_ts/detections`（rov_backend_service.dart:988, 1022-1031），但桥接转发只发 `{type,data,camera_id,seq}`（backend/app.py:332-337），组 meta 时也没拷 detections/sent_ts（app.py:306-313）。后果：rdk 模式下 ≈链路时延永远不显示（linkLatencySeconds 无 sent_ts 返回 null，rov_backend_service.dart:218）、分辨率永远 '--'，**实时检测日志/AI 识别叠加在真机上收不到任何数据**——而网关协议明明有这些字段（rdkx5/docs/UI_PROTOCOL.md §2.1）。fps 靠本地实测兜底（1026 行）尚可。
7. **两点测量的坐标算错 + 后端无实现**（代码走查）：`_onVideoTap` 用 `localPosition`（相对视频区）除以**整页** RenderBox 尺寸（main_control_desktop.dart:627-647），点会画偏；算完发的 `measure_distance` 后端不认识（backend/app.py:375-411 只处理 auth/command/set_rdk_config/get_status/get_telemetry，其余回 unknown message type），`distance` 永远不回，估计距离永远出不来。
8. **sim 遥测 0.5Hz 偏慢**（联调体验提示，非缺陷）：`sim_telemetry_loop` 2 秒一拍（backend/app.py:224），界面联调时深度/温度数字跳动明显滞后于 15fps 视频；真实 RDK 是 5Hz（UI_PROTOCOL.md §2.2），sim 若调成 5Hz 联调手感更接近真机。

## 五、建议（按优先级）

1. **急停闭环**：急停三个入口在收到 `ack.success=false` 时升级提示（红色常驻条直到恢复），`emergencyStop` 改为异步确认后才报「已急停」；未连接场景保持现有如实提示。
2. **主控页急停对齐** operate 页的「急停未发出」反馈（main_control_desktop.dart:1325 一行改动）。
3. **统一急停交互**：建议 operate 页去掉确认对话框或改为急停球同款 500ms 充能，三入口一种手感。
4. **主控页补「释放」**：加 Shift+空格 或快捷操作网格加一张「释放（吸力 0%）」卡，复用现有 `_backendService.release()`。
5. **键盘焦点自愈**：页面任意 onTap / Slider onChanged 后 `FocusScope.unfocus()` 并把焦点还给页面焦点节点。
6. **桥接层把 frame 元数据透传全**：`push_frames_to_ui` 补发 `width/height/fps/sent_ts/detections`（app.py:332-337 已有 meta 在手，app.py:306-313 把 detections 一并拷入），让 ≈链路时延和 AI 检测日志在真机活过来。
7. **两点测量**：坐标改用视频区 RenderBox；`measure_distance` 要么后端实现、要么 UI 先隐藏入口（不留无实现的入口，符合铁律④）。
8. sim 遥测提到 5Hz，贴近真机联调手感。

## 六、评分

**4 / 5。** 桥接层速度、鉴权闸门、数据真实绑定、松手即停手感都是真材实料（首帧 7.2ms / ack p50 9ms / 急停 ack ≈10ms，全部实测）；扣 1 分在 UI 层 ack 丢弃导致急停"假成功"风险、主控页急停无反馈、抓取无释放、真机元数据透传断链——都是操作员在船上真会撞上的问题。
