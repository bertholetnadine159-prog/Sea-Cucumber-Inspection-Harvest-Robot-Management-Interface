# 新用户反馈：海参捕捞机器人 SeaUI（第一次使用）

- 画像：第一次拿到这台水下海参捕捞机器人控制系统的操作员，没有读过任何手册。
- 实测方式：真实执行。独立后端实例 `ROV_BACKEND_MODE=sim ROV_WS_PORT=18714 ROV_API_PORT=15014 ROV_DB_PATH=data/uf_newbie.sqlite3 python app.py`（backend/ 目录后台运行，`curl http://127.0.0.1:15014/api/health` 就绪后返回 `{"ok": true, "backend_mode": "sim", ...}`）；REST 登录 + WS（`ws://127.0.0.1:18714`，`{"type":"auth","action":"login","token":...}`）全动线用 Python 计时；界面文案逐页通读 `rov_flutter/lib/features/**` 源码（18 个 dart 文件全部过了一遍）。
- 说明：本机未拉起 Flutter 桌面壳（任务方法未要求），界面体验基于逐页代码走查 + 真实后端协议响应，未跑 `flutter run`。

## 总体评分：3.5 / 5

鉴权动线完整且真实（没有假数据、没有假按钮复活），报错大多是中文人话；但"不看手册能不能明白每页干什么"这一条不达标——RDK/Pixhawk/链路时延等术语零解释，忘记密码是死胡同，普通用户会看到一个永远打不开的"管理员"页。

---

## 满意（带证据）

1. **首次登录强制改密动线完整、真实生效**。实测：`POST /api/login`（初始口令）返回 `must_change_password: true`（94.1ms）；改密 `PUT /api/users/1/password` 成功后用新密码重登 `must_change_password: false`（98.2ms）；旧密码再登返回 `401 {"ok": false, "error": "用户名或密码错误"}`；改回初始口令后 `must_change_password` 又变回 `true`。界面侧 `login_screen.dart:82-105` 拦截到位：改密成功前不进主界面，弹窗不可点击遮罩关闭（`barrierDismissible: false`，login_screen.dart:90）。
2. **改密弹窗文案像人话**。"当前账号仍在使用初始口令，为保障系统安全，首次登录必须修改密码。"（login_screen.dart:700）——新用户不需要手册就明白为什么要改。还给"暂不修改"出口（login_screen.dart:770），不会把人困死在弹窗里。
3. **首帧与命令应答快**。Python 计时（WS auth 用 token）：hello 68.2ms → auth 75.6ms → 首帧 76.6ms → 首条 sensors 96.5ms；`stop` 命令 ack 106.1ms 且 `success: true`。登录页到进入主控之间没有可感知的等待。
4. **无鉴权连接拿不到任何流数据，权限边界真实**。实测：未带 token 的连接发 `stop` 得到 `{"type":"ack","command":"stop","success":false,"message":"unauthorized"}`（app.py:516-528 每条命令独立校验 token）；普通用户发 `arm` 得 `success:false, "forbidden"`（危险命令白名单生效）；普通用户访问 `/api/stats`、`/api/users` 均 `403 {"error":"admin only"}`。
5. **断链与数据老化有真实提示，不是摆设**。`StaleBadge`（stale_badge.dart:45-48：5 秒无数据显示"⚠ 信号丢失"，数据恢复自动消失，断链时冻结最后真实值）；sim 模式全局黄条"⚠ 仿真数据——非真实硬件回传"（app.dart:225-239），新用户不会被仿真数据骗成真实海况。
6. **急停不装样子**。operate_desktop.dart:974-991：急停有确认弹窗，未连接时如实提示"急停未发出：后端未连接，请检查连接后重试"，不会假报"已发送"。
7. **登录错误信息是中文**。错误密码实测返回 401 `"用户名或密码错误"`（74.6ms），登录页直接展示（login_screen.dart:69-72）。

## 痛点（带证据）

1. **忘记密码是死胡同，联系方式还是占位假数据**。`forgot_password_screen.dart:10`：`kAdminContact = '管理员联系方式：电话 0000-000000 / 邮箱 admin@example.com'`。后端（backend/app.py 全文）也没有任何找回密码接口（grep `reset|forgot` 仅命中命令翻译 `resetPosition`）。第一次用的人密码输错三次后走到这页，看到 0000-000000 只能放弃。
2. **"管理员"导航对所有人可见，点进去全是失败**。`app_header.dart:80` 导航五项写死，无角色过滤；普通用户实测 `/api/stats`、`/api/users` 均 403。普通操作员每次点"管理员"都要撞一次墙，没有任何"你没有权限"的预告。
3. **设置页说"密码修改需管理员权限"，与后端行为矛盾**。`settings_desktop.dart:772`："密码修改需管理员权限，修改后即时生效。"但 backend/app.py:872-875 明确允许普通用户自助改自己密码（`if not _is_admin(user) and user["id"] != target_id` 才拒绝）。实测普通用户 token 调 `PUT /api/users/{id}/password` 是放行的。看不懂的新用户要么不敢改，要么以为系统坏了。
4. **RDK / Pixhawk / ≈链路时延 等术语零解释**。主控页标题栏芯片"RDK 链路正常 / RDK 未接入"（main_control_desktop.dart:233），右栏卡"Pixhawk 已连接"（main_control_desktop.dart:1041）、"≈链路时延 23ms"（main_control_desktop.dart:712）、"飞控状态"里还有"解锁状态/飞行模式"。我第一天上班，不知道 RDK 是板载网关、Pixhawk 是飞控、"解锁"是电调解锁不是账户解锁——每个词都得问师傅。全 UI 无一处 tooltip/帮助入口解释。
5. **操作页中心按钮写着"HOVER"，实际是"停止"**。operate_desktop.dart:896：方向控制盘中心是停止按钮，下面的徽标却写"HOVER"（旧版遗留英文）。按"前进"旁边的 HOVER？大多数新用户第一反应是鼠标悬停提示，不会想到点下去=停止。
6. **状态卡底部"实时读取中 (±0.02)"没有单位**（operate_desktop.dart:347）。±0.02 是米？摄氏度？伏特？三张卡（深度/机器温度/电池电压）共用同一行文案，完全看不出各自精度。
7. **移动端检测日志副标题直接暴露代码字段名"数据源：frame.detections"**（main_control_mobile.dart:1276）。这是写给开发者的注释，不是给船长的信息。
8. **头部用户角色显示英文原始键名**。`user_session.dart:63`：`displayRole => _currentUser?.role ?? ''`，登录后右上角显示 "super_admin"/"admin" 而不是"超级管理员/管理员"。同一页面里设置页却有中文映射"超级管理员/管理员/普通用户"（settings_desktop.dart 字符串提取可见），两套口径。
9. **顶栏通知铃铛是死按钮+永亮的红点**。`app_header.dart:166-189`：`onPressed: () {}`（空实现），红点常驻。新用户第一天会以为有未读报警，点了却什么都没有——这和"不恢复空壳功能"的项目铁律精神相悖，比没有这个铃铛更糟。
10. **没有密码规则提示，后端也不校验强度**。实测：管理员建号接口接受 1 位密码 `"1"`（`POST /api/users` 返回 200）；强制改密弹窗（login_screen.dart:616-632）只校验非空/两次一致，界面和后端（database.py:221-222 仅查空）都不告诉用户"至少几位、要不要符号"。第一次设密码全靠猜。
11. **两处"连接设置"长得很像但不是一回事**。主控页"RDK 视频源"弹窗配置的是**PC 后端**主机/端口（main_control_desktop.dart:1837-1866，提示"仅支持 RDK X5 真实视频流"），设置页"配置中心"配置的才是**RDK X5 板卡** IP/端口（"RDK X5 IP 地址/默认 8080"）。新用户连不上时不知道该改哪一个，两处文案都没有说明"这是 PC 后端/这是水下板卡"。
12. **登录失败的兜底文案会把异常原文怼给用户**。`login_screen.dart:75`：`'登录失败：$e'`——后端没起时用户会看到类似"登录失败：Failed host lookup: ..."的英文异常串（api_client.dart:63 的"无法连接本地后端服务"能兜住 HTTP 层，但兜不住这一支的展示效果）。settings/data 页也有 `'HTTP ${response.statusCode}'`（settings_desktop.dart:1034、1057）这类工程师腔错误码直出。

## 建议

1. 忘记密码页去掉占位联系方式，改成"请联系您的设备管理员在后台重置；若您就是管理员，请用初始账号登录后在『管理员 → 用户与角色』中重置"——用系统里已有的真实能力替代假电话。
2. 导航按角色渲染：普通用户隐藏（或置灰+锁形图标+"需管理员权限"提示）"管理员"入口；顺手把 `displayRole` 映射成中文（复用设置页已有的"超级管理员/管理员/普通用户"映射）。
3. 设置页那句"密码修改需管理员权限"改为"修改后需重新登录"；同时给改密弹窗补一条密码规则（建议后端同步加最小长度校验），规则写进提示文案。
4. 术语第一次出现处加一句话 tooltip 或首次引导：「RDK：水下板载网关（视频/AI 推理）」「Pixhawk：飞控（控制推进器/读取电池）」「≈链路时延：画面从水下到本屏的大致延迟」。宁可页面上多一行小字，也别让新用户去翻手册。
5. "HOVER" 徽标改成中文"停止"；"实时读取中 (±0.02)"按卡片各自单位写："实时读取中（精度 ±0.02 m）"等；删除移动端"数据源：frame.detections"或改为"来自 AI 实时识别"。
6. 顶栏通知铃铛：要么接真实告警源（遥测超时、链路断开时才亮红点），要么整个移除。
7. 两处连接设置互相注明用途，并在"视频源配置"弹窗里加一句"这里填本机 PC 后端；水下板卡地址请在『设置 → 配置中心』修改"。
8. 把 `'登录失败：$e'` 与 `'HTTP ${response.statusCode}'` 类兜底文案统一转成人话（"无法连接本地后端服务，请确认后端已启动"），异常详情进日志不进界面。

- 后端启动：`backend/` 目录，`ROV_BACKEND_MODE=sim ROV_WS_PORT=18714 ROV_API_PORT=15014 ROV_DB_PATH=data/uf_newbie.sqlite3 python app.py`；`curl /api/health` → `{"ok": true, "backend_mode": "sim", "rdk": {"connected": false, ...}}`。
