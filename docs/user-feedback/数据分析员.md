## 满意（带证据）

1. **数据真实可溯，且仿真/真实链路严格隔离（契约§8 落实到位）**
   - sqlite 直查：`sensor_readings` 共 459 行，`source` 分布 `{'sim': 459}`，无混入；表结构 `ts, source, name, value, unit, extra`（`PRAGMA table_info` 实测）。
   - sim 遥测入库时按当前模式打标：`backend/app.py:253` `db.log_sensor_snapshot(sensors, source=MODE)`；`/api/sensors` 默认 `source='rdk'`（`backend/app.py:756`）。
   - 界面同款请求（不带 source，`data_analysis_desktop.dart:198-204`）在 sim 库实测返回 `series=0`，页面空态文案"所选传感器在当前时间范围内尚无真实数据，仿真数据不计入"（`data_analysis_desktop.dart:768`）与后端行为**逐字一致**——不会把仿真曲线当成真实作业数据复盘，这正是分析员最怕的事。
   - 传感器命名全链路一致：库中 `name='ms5837_depth.depth_m'` 等 9 个键 = 协议 §2.2.1 = 页面 `_catalog`（`data_analysis_desktop.dart:85-94`）。

2. **统计摘要语义正确**：`stats` 基于窗口聚合前的原始值计算（`backend/app.py:686` 注释声明，实测验证：bucket=360 时 `avg=0.516` 与原始点 `avg=0.516118` 一致，而聚合点均值会被正弦采样拉偏）。页面指标卡 min/max/avg 直接取后端 stats（`data_analysis_desktop.dart:906-916`），缺 stats 时回退"从真实点计算"，两路都不掺假。

3. **趋势 chip 不是假数据**：由真实序列前后 1/4 段均值对比推导，点数 <8 不显示（`data_analysis_desktop.dart:456-466`）。旧版固定 `+0.05/+1.2/-0.3/+0.1` 演示值已在文件头声明不恢复。

4. **鉴权闸门可靠**：未鉴权 WS 连接 8 秒仅收 1 条 `hello`，`frame/status/sensors` 为 0 条（实测）；坏 token 被拒 `"会话无效或已过期，请重新登录"`（5.3ms）；无/假 token 访问 `/api/sensors` 均 401。

5. **参数校验完整，报错可读**：`from>to`→400 `"from must not be greater than to"`；`bucket=0`→400；`from=not-a-time`→400 带原值回显；ISO8601 与 epoch 秒双格式支持（`backend/app.py:648-677`）。

6. **空态三层齐备、不迷惑**：请求失败→错误面板"数据链路中断"+重试（`:722-747`）；成功但无数据→空态面板（`:750-774`）；快照空态→"暂无快照"+ 附注（`:1286-1309`）。sim 下 `list_snapshots` 回 `success=true` 但无 `snapshots` 负载（实测），页面准确落进"后端已受理但未回传快照列表"附注分支（`:298-306`）——空态不装死也不造假。

7. **图表卡自带新鲜度与数据量提示**：每卡标题挂 `StaleBadge`（65s 阈值，`:1093-1096`）+ "N 条数据"chip（`:1100-1107`），StaleBadge 的 Timer/AnimationController 均在 dispose 释放（`stale_badge.dart:100-106`）；页面 30s 自动刷新 Timer 也在 dispose 取消（`data_analysis_desktop.dart:136-139`），动效工具箱各控制器全部成对释放（`motion_kit.dart:225-227/271-274/416-418/564-567/698-702/868-873`）。

8. **响应性能无感延迟**：查询 4–48ms、WS auth 6.8ms、ack 9–11ms、REST 登录 90ms——分析员改时间范围/勾传感器即时出图。

## 痛点（带证据）

1. **"点数"与统计摘要语义打架**：24h 范围 + bucket=360s 时（新装系统跑了几分钟的真实场景），实测每序列聚合后 `pts=1`，但 stats 是原始值的 `min=0.42 / max=0.58 / avg=0.516`。指标卡同时显示"点数 1"（`s.points.length`，`:1016`）和三个互不相等的 min/max/avg——1 个点不可能有极差，分析员第一反应是"数据错了"。建议点数改显原始点数（后端 `data` 行数）或加"已聚合"说明。

2. **CSV 导出无 UTF-8 BOM，Excel 直接打开中文表头乱码**：写入为 `file.writeAsString(content)`（`data_service.dart:418`，默认无 BOM），表头是"时间,深度(m),水温1(°C)…"（`data_analysis_desktop.dart:353`）。中文 Windows 上 Excel 双击打开即乱码，必须走导入向导选编码——日报场景每天撞一次。另：导出的是 bucket 聚合后曲线，无"导出原始点"选项，分析员想留档原始序列做不到。

3. **页面无法切换数据源，sim 环境下整页永远是空态**：请求固定 `source=rdk`（`:198-204` 不传 source，后端默认 rdk），无 rdk/sim 切换控件。库里有 459 行 sim 数据、`source=sim` 查询 31ms 即回 3 序列，但界面上看不了。空态文案虽诚实，但对"想先在仿真里核对报表口径再上真机"的分析员是死路。

4. **部分选中传感器无数据时无反馈**：勾了 8 个 chip、只有 3 个有序列时，无数据的传感器既不画卡也不在 chip 上标注，只能逐个数卡片（`_buildChartGrid` 只渲染 `points.isNotEmpty` 的序列，`:1041`）。不知道是"没数据"还是"勾选没生效"。

5. **深度计温度序列在目录中缺失**：库中存在 `ms5837_depth.temperature_c`（51 行，实测 name 分布），协议 §2.2.1 也列出，但 `_catalog` 8 项不含它（`:85-94`）——界面无法复盘该温度，只能靠裸 API。

6. **快照画廊在非 rdk 模式的附注偏工程视角**：sim 下显示"后端已受理但未回传快照列表"（`:302-304`），用户无从判断是"真没快照"还是"链路问题"；且每张缩略图各自发一次 `fetch_snapshot` 短连接（`FutureBuilder` per tile，`:1362-1364`），快照多时连接风暴且无并发上限。

7. **时间范围选择器与样式规范不符**：STYLE_SPEC §8.4 写"分段选择器内**四段**"（`docs/STYLE_SPEC.md:364`），实际五段 `['1小时','6小时','24小时','7天','自定义']`（`:609`）。功能更好，但规范与实现二选一要改齐。

## 建议

1. 指标卡"点数"改用原始点数（后端已在响应里带 `data` 行数），或文案改"聚合点数/原始 N 点"。
2. CSV 写入前置 `\uFEFF` BOM（一行改动，`data_service.dart:418`）；增设"导出原始点"开关。
3. 分析页加数据源分段（真实/仿真，默认真实），或空态附注给出当前 source 与库内可用 source 提示。
4. 无数据的已选传感器在 chip 上做弱化标注（如加"无数据"小点）。
5. `_catalog` 补 `ms5837_depth.temperature_c`；快照缩略图改并发受控的批量预取。
6. 24h 档在数据仅覆盖数分钟时，空态/图表附注提示"数据仅覆盖最近 X 分钟"。

## 评分

**4.0 / 5** —— 数据真实性、溯源隔离、空态诚实度和性能都过硬（痛点 1/2/3 全是"太较真"之后的深水区问题，不是假数据或空壳回退类硬伤）；导出乱码与 source 不可切是日常使用中最快撞上的两处摩擦。
